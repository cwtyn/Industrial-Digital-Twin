## 2. 从布局到前端显示的完整链路(demo 侧)

1. **画线**:layout_editor 浏览器画 Line_4,导出 `Line_4.json`(含 elements 坐标 + edges + DEC 元素 + DEC attrs.db)。
2. **推导 tag**:`tags.build(spec)` 按 kind 出每个可停设备的 body/skid/tgt 三条订阅串。
3. **订阅**:`live_server.py` 连 `ws://<EMOS_HOST>/ws/emosweb`,分批 advise 订阅设备 3 点 + 决策表
   `Row[1-4][1-12] × DEC_FIELDS`(约 40 条/批,批间 0.15s),缓存 dataChange。
4. **HTTP 提供**:`GET /`(index.html)、`GET /spec`(布局坐标/edges/dec_meta)、`GET /data`(实时缓存 dev+dec)。
5. **前端渲染**:
   - 取 `/spec` 元素 → 坐标归一(minX/minY 偏移)→ vis node,坐标固定(physics 关)。
   - 取 `/data` 每约 1s 轮询 → `NODE_DS.update()` **只改色不重建**:有车绿 / 空位灰 / 无 tag 灰"无数据源"。
   - DEC 节点富浮层(4 页×12 行决策表 + dest_map 道号 chips)悬停/点击弹出。

## 3. EMOS tag 规则速查(核心)

ws: `ws://<EMOS_HOST>/ws/emosweb`

### 3.1 设备 tag(可停点位的实时值)
```
.<L3Lx_<段>[_<mid>]_<X1>_<X2>>.<IL|ILO>.SD.<点位>
```
点位(末尾):
- `M1003_BodyID` → 车身号(30 位)
- `I1030_RBDataSkidNo` → 雪橇号
- `I1031_RBDataTarget` → 目标地址(道号)

**X1/X2 由设备 kind 决定(关键,最容易错)**:
- `kind=='RB'` → `X1=X2=<pos>RB`(如 `1A060RB`)
- `kind=='LT'` → `X1=X2=<pos>LT`(如 `1C130LT`)
- `kind=='WT'` → `X1=X2=<pos>WT`

⚠️ **RB/LT 前缀必须和实际设备一致**:把 LT 当 RB 编 tag(如 `.L3L4_1C_1C130RB`)→ 返回 **WSS.Error**。
Line_4 的 `1C130RB/1C125RB/1B105RB`(id 带 RB 但 kind 是 **LT**)就是踩过这个坑。

### 3.2 决策表 tag(DEC,西门子 DB 符号直达,**无 .IL.SD. 设备层**)
```
.<L3Lx_<段>_LTxxxDecVisu>.Row[页,行].<SB|CB|AS|AA>.<字段>
```
字段与 UDT:`AS.I9999_Filtr01..05`(5 个判断条件)、`AS.I9999_Dest`(结果道号)、
`SB.S9999_Use`(启用)、`SB.S9999_Data1..5Match`/`FullMatch`/`Prior`(匹配/全配/优先级)。

### 3.3 dataChange 报文的关键点
- 返回 tag **带 plc 前缀**(如 `L3L4.` 开头),剥前缀用**通用** `first.startswith('L3')`(**不要** `== PLC`)——这样跨线设备(属于 L3L1 的 tag)也能正确收到。
- **advise 请求的 `plc` 必须等于该 tag 的线名**(如某 tag 属 L3L1 就填 `'L3L1'`),否则订阅不成功。
- 设备是一连接全量预订阅,dataChange 推回即缓存;UI 只去读缓存。

### 3.4 30 位车身号拆分
```
PIN[0:14] 车型[14:19] 颜色[19:23] 平台[23:26] Code[26:29]   (末尾字符忽略)
例 '78202664604063YM33JPZPZP_A000-' → '78202664604063' 'YM33J' 'PZPZ' 'P_A' '000'
```
- **空值判断**:全横杠(`/^-+$/`)、`---`、`...`、全非字母数字,都视为无车。

## 4. 订阅实现要点(demo live_server 已跑通)

- **分批订阅**防一次消息过多:约 40 条/批 + `time.sleep(0.15)`。
- 每台设备订 body/skid/tgt 三条;决策表按 `Row[1-4][1-12]` 展开。
- 跨线设备:从 spec/tags 得到的是本线名,但真实线可能不同 → 用 `config_Line_xx` 或 probe 裁决真实归属。
- 心跳 `/alive` 保活,断线 5s 重连并重订阅。
- 前端 `/data` 轮询缓存(memory snapshot),不改订阅。

## 5. 前端 vis.network 要点(从 make_line_viz 移植 + demo 验证)

- vis-network **9.1.9**,`<script src="https://unpkg.com/.../umd/vis-network.min.js">`(离线可内联升级版)。
- `physics:false` + 节点坐标固定(flow 式),`apply()` 建一次网络。
- **实时更新用 `NODE_DS.update([...])` 只改节点颜色/标题,不重建网络**(保持缩放/拖拽/选中)。
- **vis tooltip 只走 innerText**,只能用 `\n` 拼多行,**不能放 HTML** → 放不下决策表的富内容时,必须用独立 HTML 覆盖层(`position:fixed` div)。
- **事件参数差异(极易踩)**:
  - `hoverNode` / `blurNode` → **`params.node`(单数)**
  - `click` / `doubleClick` → **`params.nodes`(数组)**
  - 取节点→屏幕坐标用 `net.canvas.coordinateToDOM(net.getPosition(id))`(不是 `canvasToDOM`)。
- 决策点若"悬停没反应",先怀疑渲染路径里某个 `getElementById` 拿到的容器不存在,导致**早于 `display:block` 抛异常被吞**。
- 缩放大节点到方正:用 `widthConstraint/heightConstraint: {minimum:又,maximum:又}`。

## 8. DEC 决策表搬进 codes/ 管线 + 订阅存量补齐(2026-11-06)

本节沉淀「决策表从 demo 搬进现实线管线」期间踩的坑,核心结论是:**EMOS 订阅的真正难点不在协议,
而在大批量铺发的时序与丢块恢复**。

### 8.1 决策表 DB 符号订阅格式(与设备 tag 不同)

```
.<L3Lx_<段>_<LT|RB>xxxDecVisu>.Row[页,行].<AS|SB>.<字段>     Line_4 家族
.<L3Lx_<段>_DecPoint_<挂靠设备>.Row[页,行].<AS|SB>.<字段>     Line_1/Line_2 家族
```
- **直达 DB 符号,不带 `.IL.SD.` 设备层**(与设备 body tag 不同)。
- **前导点必须带** `.`(剥点 → `WSS.Error` 收不到 dataChange);`plc` = 各线线名。
- 两家族字段路径一致:`Row[p,r].AS.I9999_Dest|I9999_Filtr01..05`、`Row[p,r].SB.S9999_Use|FullMatch|Prior|Data1..5Match`。
- `WSS.Error`(ActiveCasServer/Session 通知)是**连接级 session 帧**,不是点位错;判断订阅是否有效**只看 `dataChange` 是否回值**。

### 8.2 真机字段现实(与 demo 文档不同,别照抄 UDT 全字段)

真机 EMOS 只**稳定**回 7 个字段:`Dest` / `Use` / `Filtr01..05`。

| 字段 | 真机实况 |
|---|---|
| `AS.I9999_Dest`、`SB.S9999_Use`、`AS.I9999_Filtr01..05` | ✅ 稳定回,有数据处必回 |
| `SB.S9999_Data1..5Match`、`SB.S9999_FullMatch` | ❌ **完全不回 dataChange** |
| `SB.S9999_Prior` | ⚠️ 不稳定(各 DEC 回 48/0/1/26 不等) |

→ 富表只做 判断条件(F1-5)/结果(Dest→道号)/启用(Use)三组,`DEC_FIELDS` 定格 7 字段(=4224 订阅)。
照抄 demo 的 14 字段会白订 7392 条且多出的仨字段永远空。

### 8.3 EMOS `advise` 协议的关键事实(probe 实测钉死)

**每次 `advise` 都会重推当前值** —— 没有去重、无需退订,重订同一 tag 必回当前值。
真正要防的是**连发节奏**,不是"重复订阅":

| 连发方式 | 结果 |
|---|---|
| 大批量快速连发(128 条 / 28 条) | 随机**漏掉整块**(128→只回 4 行;28→只回 7 格;某 DEC 384 格→下次只剩 19) |
| 小批量 / 单条(1-2 条,带间隔) | **全回**,零丢失 |

- 漏块 = **订阅侧**丢,不是 PLC 没数据。而 DEC 值是静态的,**错过初始回推后不再变、永不重推** → 必须主动补齐。
- probe 脚本自己也受此影响:写批量 probe 判断"PLC 有没有这行",若用快速连发会把漏块误判成"PLC 稀疏"。

### 8.4 大批量铺发的三类坑与处理(都写在 `workshop_source.py`)

| # | 症状 | 原因 | 处理 |
|---|---|---|---|
| 1 | `连接失败 timed out` 反复重连、vehicles=0 | 铺发(~7900 条)结束前没人读 socket,EMOS 应答塞满接收缓冲 → `send` 卡 30s 超时丢连接 | **边发边排空**:每批 advise 后 `_drain_while`(0.05s 非阻塞收帧暂存 `_prefetch`),主循环先消费 `_prefetch`;`create_connection(timeout=90)` |
| 2 | 初始铺发随机漏整块 DEC | 一批 400 连发太猛 | 初铺降到 **60/批** + `_drain_while` + 0.08s 间隔 |
| 3 | 补齐补不动、后半 DEC 冻结在低格数 | 补齐只在「收到帧」时触发;EMOS 静默时 `recv()` 永久阻塞 → 补齐停摆 | 主循环 **`ws.settimeout(0.2)`**,recv 超时(空闲)也推进补齐(超时≠断线,按 `'timed out' in str(e)` 区分) |

### 8.5 存量补齐 backfill 的正确姿势

针对「初始铺发漏块、静态值永不重推」,解法是**追踪还没回过值的格 → 分批重订直到铺满**:

- 建 `_dec_expect`(由 dec point tag 抽 `node|页|行|grp.字段`,value=(plc,tag))与 `_dec_seen`(收到 dataChange 就记)。
- 每次补:`pending = expect - seen`,对它重发 advise。
- **小批量 25/批 + 限速 0.2s**(否则补发又触发 §8.4 的漏块)。
- **终止靠「未回格清零」,绝不按墙钟冻结**(数据静态,错过永不重推;停止=永久缺)。
- **每格设重试上限 `_DEC_MAX_TRIES=10`**:超限仍不回 → 认定无法回值、放弃,既保证收敛结束又防死循环。
  (早期版本用「600s 安全上限」实测会在收敛途中冻结,导致末尾 DEC 整块缺失——别再把时间当终止条件。)
- 每连接重置 `_dec_seen`/`_dec_tries`/`_connect_ts`/`_bf*`(断线重连后重头补)。
- 结果:Line_1 10 + Line_2 2 + Line_4 11 = **全部 23 个决策点稳定收敛到 336/336(4页×12行×7字段)**,车辆 157~183 正常,无连接死亡。

### 8.7 解析热点的性能坑(追加线后暴露)

`make_extra_resolver` 原实现**对每一帧线性遍历全部订阅 tag 做子串匹配**。DEC 只有 3696 条时还能跑,
扩到 Line_1+Line_2+28 共 7728 条后,每帧 O(7728) 扫描 → CPU 跟不上帧速 → 补齐吞吐掉到 ~4/s(表面像"EMOS 慢")。
修法(语义不变):**精确字典 O(1) 快路径** → 带 plc 前缀(`L3Lx.`)剥段再查 → 设备 body/skid/target 帧直接返回 None(短路)
→ 仅少量异常 tag 才走兜底子串。加线后必须复查这类"每帧遍历全表"的实现。

### 8.6 探针(probe)使用禁忌

- **单连接多 tag**(`probe_tag.py` 一次连、批量订),服务器对快速重连有频限,逐条新连接会触发 `WSS.Error` 误报。
- **一次只一个活跃 session**:管道握着 EMOS 连接时,probe 结果无效(服务器只服务一个活跃会话)。
- **判断"PLC 到底配没配这行/字段"必须小批量/单条慢速验证** —— 批量 probe 会连发丢块,把漏块误判成稀疏。
  (本 session 曾误判 045/100/105/295 稀疏,实为 probe 自己丢块;慢速重订后全 48 行齐、Dest 都是有效道号。)
